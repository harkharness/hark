O que dá pra construir sem virar um cliente git
O Claude Code já é um cliente git bom, e a F8.0 do plano diz para parar de persegui-lo em transcript, editor e árvore de arquivos. O que ele NÃO faz é o que o Hark faz: saber o estado de N trabalhos em N repositórios ao mesmo tempo.

Já existe, é só expor

GitCli lê branch, sujos e 3 commits em 60 linhas, com o seam puro isolado. Só alimenta o prompt — e só quando a pergunta tem palavra de git.
Cada task já sabe seu workspace, e o board/sidebar já renderizam por task.
Já rodamos comando local no terminal da janela — commit e push não pedem plumbing novo.
O worker já commita quando você pede — o que falta é o Hark saber que aconteceu.

Novo, e barato

Estado do repo por task: branch, sujo/limpo, à frente/atrás. Um comando, cacheado, sem custo de token.
PR e CI pelo gh do usuário — mesma conta que ele já usa no terminal, zero token, zero chave nova. Sem gh, some.
Vínculo task ↔ branch/PR: gravado quando o worker cria a branch, é o que liga conversa e trabalho.
Voz: "o que falta commitar?", "abre o PR dessa task", "o CI passou?" — local, sem custo.

Fora, de propósito

Visualizador de diff com árvore de arquivos: é o que a F8.0 chama de esteira rolante, e o app oficial já está aberto ao lado.
Merge, rebase, resolução de conflito. Terminal existe e é melhor nisso.
Escrever a mensagem de commit com LLM sozinho. O worker já faz quando você pede; um botão que gasta token calado contraria o resto do produto.
Token do GitHub dentro do Hark. Se o gh não estiver logado, a feature simplesmente não aparece.
Três pegadinhas reais. O workspace de uma task costuma ser um subdiretório do projeto, e nada no código resolve a raiz do repositório hoje — sem isso o chip mente. RepoStatus não é serializável: não cruza o IPC como está. E commit/push devem reusar o padrão que já existe: colar no terminal sem executar.
Ordem. Primeiro o estado do repo por task, sem GitHub nenhum — já paga o chip, o card e a voz. Depois gh para PR e CI, atrás de detecção.
O gate. Depois da FASE 9: git por task encosta nas mesmas superfícies que o registry de agentes.
